# Agente de Refatoração de Lambda Unificado

## Propósito
Automatizar a consolidação de múltiplos Lambda handlers (GET, POST, PUT, DELETE) em um único handler com roteamento inteligente.

## Como Usar

### Ativar o Agente
Use este agente quando precisar refatorar uma aplicação que segue o padrão de múltiplos handlers por recurso.

```
@lambda-unifier refactor [projeto] [recurso]
```

### Exemplos de Uso

```
@lambda-unifier refactor . Users
@lambda-unifier refactor ./backend Companies
@lambda-unifier refactor . Sales --keep-public-endpoints
```

## Funcionalidades Principais

### 1. Análise Automática
- Escaneia arquivos de API para encontrar handlers (list, listById, create, update, delete, listAll)
- Identifica configuração do Serverless (YML, serverless.ts, etc)
- Valida dependências necessárias
- Detecta endpoints públicos que devem ser preservados

### 2. Refatoração de Arquivo API
- Converte `module.exports.list` → `const list`
- Converte `module.exports.listById` → `const listById`
- Adiciona import do `createRouter`
- Cria export unificado com `module.exports.handler`

### 3. Geração do Router
- Cria `requestRouter.js` se não existir
- Implementa roteamento baseado em:
  * HTTP Method (GET, POST, PUT, DELETE)
  * Path Parameters (`{id}`, `/all`, `/delete`)

### 4. Atualização de Configuração
- Consolida múltiplas funções Lambda em uma no serverless.yml
- Agrupa todas as rotas (GET, POST, PUT, DELETE) em um único handler
- Preserva endpoints especiais (públicos, eventos, etc)

### 5. Validação
- Testa sintaxe Node.js
- Valida que nenhuma funcionalidade foi perdida
- Sugere checklist de testes

## Padrão de Handlers Reconhecidos

O agente detecta automaticamente esses handlers:

```javascript
module.exports.list = async (event) => { ... }
module.exports.listById = async (event) => { ... }
module.exports.listAll = async (event) => { ... }
module.exports.create = async (event) => { ... }
module.exports.update = async (event) => { ... }
module.exports.delete = async (event) => { ... }
```

## Padrão de Roteamento Gerado

| Método | Caminho | Handler |
|--------|---------|---------|
| GET | `/resource` | list |
| GET | `/resource/{id}` | listById |
| GET | `/resource/all` | listAll |
| POST | `/resource` | create |
| POST | `/resource/delete` | delete (batch) |
| PUT | `/resource` | update |
| DELETE | `/resource/{id}` | delete |

```bash
#!/bin/bash

```

## Opções e Flags

### `--keep-public-endpoints`
Preserva endpoints públicos (sem autenticação) como handlers separados.

```
@lambda-unifier refactor . Sales --keep-public-endpoints
```

### `--dry-run`
Simula a refatoração sem fazer mudanças.

```
@lambda-unifier refactor . Products --dry-run
```

### `--create-router-only`
Apenas cria o router, não refatora os arquivos.

```
@lambda-unifier create-router ./backend
```

### `--validate-only`
Valida se o projeto pode ser refatorado.

```
@lambda-unifier validate ./backend
```

## Detectando Padrões

O agente identifica automaticamente:

✅ Padrão RESTful com múltiplos handlers
✅ Endpoints especiais (`/all`, `/delete`, `/contract`)
✅ Autenticação e autorização
✅ Conexões com banco de dados
✅ Upload/manipulação de imagens
✅ Validações customizadas

## Pré-requisitos

- Node.js 14+
- NPM ou Yarn
- Acesso ao repositório
- Permissão para criar/modificar arquivos

## Limitações Conhecidas

- ⚠️ Não refatora handlers muito customizados com lógica compartilhada
- ⚠️ Endpoints com múltiplos path parameters precisam validação manual
- ⚠️ Handlers com websockets ou streaming precisam ajuste manual

## Troubleshooting

### Erro: "Cannot find handlers"
- Verifique se o arquivo API segue o padrão `module.exports.list = async`
- Use `@lambda-unifier analyze` para validar

### Erro: "queryStringParameters is null"
- O router foi atualizado para inicializar `event.queryStringParameters = {}`
- Isso é automático no `createRouter`

### Handlers não encontrados após refatoração
- Execute `@lambda-unifier validate` para identificar problemas
- Verifique imports e exports no arquivo refatorado

## Suporte

Para problemas com a refatoração:
1. Verifique o arquivo `.agents/lambda-unifier.log`
2. Execute com `--verbose` para mais detalhes
3. Use `--dry-run` para simular sem modificar
